# Implement robust 3D n-gon triangulation and near-uniform-area remeshing in C11

You are the coding agent. Build and deliver a standalone C11 library, a small command-line driver, a Lean 4 verification project, and reproducible tests. Inspect the repository first and reuse its build and test conventions where applicable. Implement the production geometry and topology yourself. Use external mesh libraries only in optional, separate comparison tools. Complete the milestones in order and record the commands, results, and remaining limitations in the repository.

## 1. Input, output, and surface semantics

- Accept one ordered, oriented 3D outer ring and zero or more ordered hole rings. Support concavity and retained collinear boundary vertices. An optional feature consists of tagged seed-triangulation edges and pinned vertices. General interior constraint insertion and feature detection are extensions. An input can provide an explicit chart axis or request deterministic automatic selection.
- Define finite IEEE binary64 inputs as the exact dyadic values received. Require a supported binary64 layout for that adapter and provide a lossless rational fixture and certificate format. Reject NaNs, infinities, repeated vertices or closure records, zero-length edges, backtracking, crossings, nonincident contacts, overlapping segments, and holes that touch, overlap, nest, or lie outside the outer ring. Report original ring, edge, and vertex IDs where available. Signed zero has one geometric value. Accept either winding for the outer ring and require opposite winding for holes after projection. Preserve the chosen outer orientation in the output.
- Select an axis-aligned chart by dropping one coordinate. Compute the outer ring's signed projected areas exactly. Try axes by descending absolute area with fixed axis-index ties, or try only the requested axis. Accept the first chart that passes all exact planar-domain tests. Require nonzero ring areas and projection injectivity on the boundary, including across rings. Reject with chart diagnostics if no supported chart works. Use a fixed axis permutation and sign convention so internal triangles have positive chart orientation. Record the transform and winding in the result.
- **Strict planar mode.** Find an exact noncollinear triple, verify coplanarity with exact orientation, and use its plane to define the lift. A supported projection and valid rings define the entire planar region. Document that CDT in an axis-drop chart uses the chart metric. If a physical planar CDT is desired later, use the plane-induced metric and independently specify and test its predicates.
- **Graph mode.** Build a deterministic projected triangulation and lift its vertices to the original 3D coordinates. The resulting piecewise-linear height function defines the reference surface. Two diagonal choices on a warped quadrilateral can give different reference surfaces. Freeze the seed connectivity and coordinates once selected. Expose seed algorithm, chart, and tie-breaking version in metadata. Exact planarity and near-planarity diagnostics may guide callers. They may never silently change the surface definition.
- **Graph remeshing.** Optimize an embedded piecewise-linear graph over the same projected domain. Default to exact preservation of the seed surface, with an optional explicit height tolerance for approximation. The height-tolerance option bounds displacement in the dropped-coordinate direction and gives a symmetric Euclidean Hausdorff upper bound by matching equal chart coordinates. It does not bound normal deviation. Compare affine heights at every vertex of the overlay of old-reference and candidate triangles. Include edge crossings, vertex contacts, and endpoints of coincident intervals using exact rational constructions. Every affected point lies in a convex overlay cell on which the difference is affine. In exact mode, protect seed edges separating distinct affine height planes and keep their endpoints pinned. Edits inside an affine patch can then use its exact lift. Keep those implicit crease constraints even if the user supplies none.
- Keep original boundary segments fixed by default. Optionally permit a constraint edge to become an ordered chain with exactly the same 3D image, shared by all incident triangles. Keep original endpoints and tagged corners pinned. Subdivision must preserve tags, order, and exact segment parameters. For multiple n-gons sharing an edge, either use fixed boundaries or coordinate the shared subdivision externally and verify the assembled mesh. A patch success does not certify the embedding of an entire asset.
- Return indexed triangles, exact vertex coordinates, source/provenance IDs, constrained chains, chart and reference metadata, and validation and quality reports. Expose explicit statuses for invalid input, unsupported chart, exhausted resources, allocation failure, internal error, valid mesh with targets unmet, and valid mesh with targets met. Return mesh data only when it passes the stated validity contract. Binary64 export is a separate operation with checked rounding, revalidation of the exported coordinates against the requested contract, and explicit failure when rounding cannot preserve it. Include this distinction in the API documentation.

## 2. Exact predicates, constructions, and data structures

1. Implement signed integers using checked allocation and unsigned fixed-width limbs, plus normalized rationals with positive denominators. Use portable C11 operations and document word-size requirements. Implement a binary64 decoder with bit copies and explicit normal, subnormal, and zero handling. Bound input size, allocation, operation counts, and integer growth through caller-configurable limits. Abort a predicate or edit cleanly if its exact result exceeds those limits. Propagate an error through every caller.
2. Start with exact signs for orient2d, orient3d, incircle with orientation convention, segment incidence and intersection classification, and point-in-ring with a half-open ray rule. Define zero results explicitly. Use rational constructions for split points, affine lifts, overlay vertices, and distances used by strict comparisons. Filtered predicates are a later performance milestone. Accept a floating sign only when a derived error bound certifies it under the actual arithmetic environment. On uncertain sign, unsupported rounding, overflow, or underflow risk, use the exact path. Never use a tolerance to resolve a topological sign. Compare fast and exact paths before making filters the default.
3. Use stable vertex IDs, indexed triangles, and explicit oriented edge incidence with at most two incident faces. Store constraints separately from transient edge indices, including chain parameters and provenance. Build a slow independent validator first, then add conservative spatial indexing as needed. Use closed exact AABBs or outward-rounded bounds. An uncertain broad-phase test must keep the pair.
4. Check all allocation multiplications, index conversions, and integer operations that can overflow. Use transactions or a staging mesh so rejected edits and resource failures preserve the last validated mesh. Document ownership, lifetime, thread-safety, and deterministic iteration. Keep traversal order independent of pointer values, hash seed, and allocation order.

## 3. Seed triangulation

- Validate the planar straight-line boundary and derive the domain from its oriented rings. For the baseline, support simple rings and holes by a deterministic planar straight-line graph construction. Enumerate vertex pairs in stable order, adding visible diagonals whose open interiors lie in the domain and meet existing segments only at common endpoints. Reject diagonals through any third vertex. Use exact midpoint classification after boundary intersection checks. Maintain all original boundary subdivisions. Extract bounded faces with a rotation system ordered by exact half-plane and cross-product comparisons. Traverse all half-edge cycles, classify the domain side using an exact witness immediately to the left of a directed edge, and group cycles where necessary. Construct the witness by halving a rational offset until its open path from the edge midpoint crosses no segment, subject to the resource budget. This avoids choosing a centroid of a nonconvex cycle or treating a hole interior as a domain face. Require positive triangular faces, all original vertices represented, and full domain validation. Prove or document why maximality yields triangles for the admitted domains, including collinear chains and holes. Keep this high-cost baseline as a reference when adding a faster seed method.
- Improve the seed with Lawson flips on unconstrained, strictly convex quadrilaterals. Use strictly positive orientation-correct incircle violations and retain cocircular diagonals. Process a stable work queue with an explicit operation budget. Validate projected local Delaunay legality on all unconstrained flippable edges before claiming CDT. If a budget stops legalization, report the validated seed and its incomplete legalization status. When accepting caller-supplied feature edges, require them to appear in the frozen seed and validate the resulting constraint graph.
- Check edge incidences, duplicate faces, exact chart orientation, triangle pair intersections, and domain coverage before lifting. Shared IDs permit precisely their shared simplex. A pair sharing an edge can still overlap in area. A pair with distinct IDs touching geometrically is invalid. Preserve this classification in the 3D audit, including coplanar overlap, noncoplanar crossings, isolated contacts, and adjacent pairs. For a standalone certified graph patch, projection already proves 3D embedding. Implement an independent rational 3D audit for regression tests, exported output where applicable, and assembled-patch validation. An exact triangle-plane cut followed by rational interval overlap on the plane intersection line handles noncoplanar pairs. Reduce coplanar pairs to exact planar tests by dropping a valid axis. Reject degenerate triangles before either path.

## 4. Remesh for physical area

- Accept a target physical triangle area or a target count. For count mode, derive the target from reference 3D area divided by count, round it once to a documented positive rational using certified bounds, and report both that target and the actual count. Hold the chosen target fixed throughout a run. For each triangle use A = ||(b-a) × (c-a)|| / 2 in 3D. Use exact squared area for hard thresholds when possible and certified bounds for any hard threshold involving sums of square roots. Approximate metrics may rank candidates. Seed a length proposal with the equilateral relation h = sqrt(4 A_target / sqrt(3)). A chart length or equal chart area alone is insufficient on a sloped surface.
- Use a bounded deterministic schedule of edge splits, interior triangle splits, collapses, flips, and vertex relocation. Propose splitting large faces or long edges and collapsing short interior edges. Use stable edge/face IDs to break ties, and put a cap on passes, edits, vertex count, and candidate evaluations. A triangle centroid split gives exact equal-area children on the original triangle. Check conformity when splitting an edge and update both incident faces atomically. Choose relocations using one-ring averaging or a local area objective, with bounded step reduction and explicit chart-domain checks. In approximation mode lift newly placed chart coordinates using the frozen reference, then validate the entire candidate patch against the height bound.
- Score candidates using area error and shape separately. Start with mean squared log area ratio as the area term and a low mean-ratio penalty, where mean ratio is 4 sqrt(3) A divided by the sum of squared edge lengths. Use local deltas for ranking, a fixed deterministic comparison policy, and checkpoint the best fully validated mesh by a documented global objective. Require strict objective improvement for flips and relocation and use split/collapse hysteresis to limit cycling. Track independent validity and objective rejection counts. Allow hard caller-specified constraints to block otherwise desirable edits.
- Reject edits that remove or move pinned vertices, alter constrained chains without authorization, cross a crease or boundary illegally, invert or degenerate a face, change topology, introduce forbidden intersections, or violate the reference bound. For collapses, check the simplicial link condition and apply the stated boundary policy. Check vertex links as a single cycle for interior vertices and a single path for boundary vertices. Check orientation, connectedness, all boundary cycles, and Euler characteristic 1 minus hole count as corroborating evidence. Link and Euler checks alone do not establish embedding or domain coverage.
- Before committing a candidate, validate the changed neighborhood against itself and the unchanged mesh. Require the old and new projected patch boundaries to agree as oriented chains, allowing approved subdivision, or use a full domain check. Keep the final independent validator mandatory. Measure both improved and stagnant runs. Report budget exhaustion, constraint-limited edits, numerical resource limits, and quality targets unmet. Arbitrarily acute corners, fixed segments, narrow channels, and creases can prevent any requested area/shape combination.

- **Geometry and topology tests.** Freeze fixtures for convex and concave rings, reversed winding, retained collinear vertices, holes, projection collisions, self-crossings, repeated vertices, nonplanar saddles, twisted quads, overhangs with no supported chart, and large coordinate offsets. Include exact chart selection ties and adjacent coplanar triangle overlap. In 3D test skew disjoint pairs, coplanar overlap, edge sharing, point sharing, and unexpected contact. Include close but disjoint sheets in assembled meshes. Test reversed axes and exactly representable scaling and translations with the chart fixed where appropriate. Assert invariants rather than identical diagonal choices when a transform changes chart selection or legal ties.
- **Remeshing tests.** Cover fixed segments, explicitly subdividable boundaries, sharp creases, pinned vertices, thin channels, holes, and an area target made impossible by fixed constraints and a small face budget. Add a warped fixture where both triangulations match vertex heights but differ at a diagonal crossing. Exercise zero tolerance, an exact positive height limit, and a limit exceeded only at an overlay vertex. Test budget exhaustion, reproducibility, transactional rollback under injected allocation failures, and output rounding failures.
- **Quality gate.** Freeze fixture geometry, seed policy, target, budgets, and statistics before tuning. On a 1×1 planar square and a well-conditioned concave planar fixture with boundary subdivision enabled, use target count 128 and require final area CV at most 0.30, at least 90% of faces in [0.5, 1.5] times the target area, and a fifth-percentile minimum angle of at least 20 degrees. On an unbalanced seed with interior refinement, require at least 25% reduction in mean squared log area ratio, together with invariant preservation. Report the same area and shape statistics on warped and constrained fixtures, with fixture-specific thresholds only where the geometry makes them meaningful. Treat the numeric gates as engineering benchmarks and record failures without silently weakening them. Report CV, area ratio quantiles, min-angle quantiles, achieved count, reference deviation, edit counts, runtime, and peak memory. - **Independent checks.** Compare optional CGAL runs for equivalent projected domains, constraints, area/shape statistics, and legal CDT predicates. Cross-check broad-phase results against all-pairs exact checks, and compare C and Lean checkers using valid and deliberately mutated certificates. Fuzz both input and certificate parsers, seed construction, and randomized edit sequences with reproducible seeds. Include a known adversarial case for each bug found.
- **Release gate.** All declared valid fixtures pass the mandatory validator, all declared invalid inputs return their documented error class, the Lean soundness proofs pass the kernel-backed build and every result advertised as certified passes the executable check, and all corruption fixtures fail where expected. Build in strict C11 with GCC and Clang, warnings enabled, and run AddressSanitizer and UndefinedBehaviorSanitizer on test workloads. - Use CGAL's support-plane/CDT workflow and isotropic local operations as baselines. The independent implementation deliberately chooses an exact axis-drop chart and a graph contract for predictable nonplanar semantics. Consult the 6.2 release notes and versioned API for triangulation hooks and constraints. Use the 2025 ACVD and almost-planar remeshing announcement as context for vertex-count-driven comparison and planar patch handling. ACVD's distribution objective differs from directly controlling physical triangle area. - Use Shewchuk for robust orientation and incircle signs, filter design, and the conditions on adaptive arithmetic. [Robust predicates and paper](https://www.cs.cmu.edu/~quake/robust.html) · [Delaunay refinement papers and thesis](https://www.cs.cmu.edu/~jrs/jrspapers.html)
- Lipschütz, Reitebuch, Polthier, and Skrodzki (2026) study manifold meshing and feature-aware remeshing with a lower edge-length bound under their algorithm's assumptions. Use the paper to guide explicit feature constraints, short-edge statistics, and documentation of theorem hypotheses. Their edge-length and manifold results do not transfer to a different optimizer.
